## Перевірка API

### 1. Створення тестового двійника

**Команда:**

```bash
curl -i -u ditto:ditto -X PUT -H "Content-Type: application/json" \
-d '{"attributes": {"purpose": "перевірка"}}' \
http://localhost:8080/api/2/things/org.pzks:test-1
```

**Відповідь:**

```http
HTTP/1.1 204 No Content
Server: nginx
Date: Sat, 07 Nov 2026 23:06:22 GMT
Connection: keep-alive
correlation-id: 449f6e6b-f75c-42a0-9921-f168a547ec94
ditto-originator: nginx:ditto
entity-revision: 1
response-required: false
etag: "rev:1"
```

Запит успішно оброблено. Сервер повернув статус `204 No Content`, тобто операцію виконано без повернення тіла відповіді.

### 2. Отримання створеного двійника

**Команда:**

```bash
curl -u ditto:ditto http://localhost:8080/api/2/things/org.pzks:test-1
```

**Відповідь:**

```json
{
  "thingId": "org.pzks:test-1",
  "policyId": "org.pzks:test-1",
  "attributes": {
    "purpose": "перевірка"
  }
}
```

Отримана відповідь підтверджує наявність цифрового двійника з ідентифікатором `org.pzks:test-1`, прив'язаною політикою доступу та атрибутом `purpose`.

### 3. Перевірка згенерованої політики доступу

**Команда:**

```bash
curl -u ditto:ditto http://localhost:8080/api/2/policies/org.pzks:test-1
```

**Відповідь:**

```json
{
  "policyId": "org.pzks:test-1",
  "imports": {},
  "entries": {
    "DEFAULT": {
      "subjects": {
        "nginx:ditto": {
          "type": "generated"
        }
      },
      "resources": {
        "thing:/": {
          "grant": ["READ", "WRITE"],
          "revoke": []
        },
        "policy:/": {
          "grant": ["READ", "WRITE"],
          "revoke": []
        },
        "message:/": {
          "grant": ["READ", "WRITE"],
          "revoke": []
        }
      },
      "importable": "implicit"
    }
  }
}
```

Для тестового двійника автоматично створено політику доступу `org.pzks:test-1`. Вона містить запис `DEFAULT`, у якому суб'єкту `nginx:ditto` надано права читання (`READ`) і запису (`WRITE`) для ресурсів `thing:/`, `policy:/` та `message:/`.

## Структура двійника

Структура цифрового двійника електроскутера передбачає зберігання паспортних властивостей, поточних параметрів стану, доступних функцій та зв'язків з іншими цифровими двійниками.

| Елемент | Вид | Ditto | Джерело |
|---|---|---|---|
| Тип об'єкта | паспорт | `attributes/objectType` | Опис об'єкта ЛР 1 |
| Швидкість руху | стан | `features/runningGear/properties/speed` | `SIG_VEL_01` |
| Частота обертання двигуна | стан | `features/motor/properties/rpm` | `SIG_RPM_02` |
| Струм акумулятора | стан | `features/battery/properties/current` | `SIG_CUR_03` |
| Напруга акумулятора | стан | `features/battery/properties/voltage` | `SIG_VOL_04` |
| Температура електродвигуна | стан | `features/motor/properties/temperature` | `SIG_TMP_05` |
| Рівень заряду батареї | стан | `features/battery/properties/stateOfCharge` | `SIG_SOC_06` |
| Стан гальмування | стан | `features/brakes/properties/active` | `SIG_BRK_07` |
| Стан протиугінного блокування | стан | `features/security/properties/locked` | `SIG_LCK_08` |
| Зміна обмеження максимальної швидкості | функція | Повідомлення `inbox/setSpeedLimit` | Оператор |
| Активація протиугінного блокування | функція | Повідомлення `inbox/activateLock` | Оператор |
| Належність акумулятора до електроскутера | зв'язок `partOf` | `attributes/partOf` (`thingId`) | Структура об'єкта |

### Представлення зв'язків

У Eclipse Ditto немає окремої сутності для представлення зв'язків між цифровими двійниками. Тому зв'язок зберігається як атрибут одного з двійників, значенням якого є ідентифікатор іншого двійника (`thingId`).

Наприклад, якщо акумулятор представлений окремим цифровим двійником, його атрибут `partOf` може містити ідентифікатор цифрового двійника електроскутера. Таким чином фіксується відношення належності акумулятора до електроскутера. Семантичний зміст такого зв'язку визначається онтологією.

Зазначений зв'язок передбачає окреме представлення акумулятора як цифрового двійника. Якщо акумулятор моделюється лише як компонент електроскутера, окремий зв'язок через `thingId` не створюється.

## Порівняння платформ

Для вибору платформи цифрового двійника порівняно Eclipse Ditto, Azure Digital Twins та AWS IoT TwinMaker. Оцінювання виконано за шкалою від 1 до 5, де 1 означає найнижчу відповідність критерію, а 5 — найвищу.

### Критерії та ваги

Ваги критеріїв визначено до оцінювання платформ. Найбільшу вагу надано відкритості, оскільки для навчального проєкту важливо використовувати платформу з відкритим вихідним кодом. Також важливою є можливість локального розгортання, щоб не залежати від зовнішньої хмарної інфраструктури.

| Критерій | Вага | Обґрунтування |
|---|---:|---|
| Відкритість | 0,25 | Враховує ліцензію, доступність вихідного коду та формат моделі |
| Масштабованість | 0,20 | Здатність підтримувати збільшення кількості двійників та обсягу даних |
| Вартість володіння | 0,20 | Враховує витрати на інфраструктуру, розгортання та використання |
| Локальне розгортання | 0,15 | Можливість запуску платформи на власній інфраструктурі |
| Підтримка протоколів | 0,10 | Можливості інтеграції з іншими компонентами системи |
| Зрілість спільноти | 0,10 | Наявність документації, прикладів використання та підтримки розробників |
| **Сума** | **1,00** | |

### Обґрунтування оцінок

**Eclipse Ditto**

- **Відкритість (5):** платформа є відкритим програмним забезпеченням Eclipse Foundation. Модель цифрового двійника представлена у форматі JSON.
- **Масштабованість (4):** мікросервісна архітектура дає змогу масштабувати окремі компоненти платформи.
- **Вартість володіння (4):** відсутня плата за ліцензію, але необхідно самостійно забезпечувати інфраструктуру та обслуговування.
- **Локальне розгортання (5):** підтримується розгортання на власній інфраструктурі за допомогою Docker.
- **Підтримка протоколів (5):** підтримує MQTT, AMQP, HTTP та Apache Kafka.
- **Зрілість спільноти (3):** має офіційну документацію та відкритий репозиторій.

Джерела:
- https://eclipse.dev/ditto/
- https://eclipse.dev/ditto/basic-connections.html
- https://github.com/eclipse-ditto/ditto

**Azure Digital Twins**

- **Відкритість (3):** використовує відкриту мову опису моделей DTDL, але сама платформа є керованим комерційним сервісом Microsoft.
- **Масштабованість (5):** хмарна архітектура підтримує роботу з великими графами цифрових двійників.
- **Вартість володіння (3):** вартість залежить від використання сервісу та пов'язаних ресурсів Azure.
- **Локальне розгортання (1):** платформа надається як хмарний сервіс і не передбачає повноцінного самостійного локального розгортання.
- **Підтримка протоколів (3):** має API та механізми інтеграції з іншими сервісами Azure і зовнішніми системами.
- **Зрілість спільноти (4):** має документацію, SDK та розвинену екосистему Microsoft Azure.

Джерела:

- https://azure.microsoft.com/en-us/pricing/details/digital-twins/

**AWS IoT TwinMaker**

- **Відкритість (2):** є керованим сервісом AWS, а модель сутностей і компонентів використовується в межах екосистеми платформи.
- **Масштабованість (5):** хмарна інфраструктура AWS дає змогу масштабувати рішення відповідно до потреб системи.
- **Вартість володіння (3):** вартість залежить від використання сервісу, кількості запитів та пов'язаних ресурсів AWS.
- **Локальне розгортання (1):** сервіс надається через інфраструктуру AWS і не передбачає повноцінного локального розгортання.
- **Підтримка протоколів (3):** інтеграція з джерелами даних реалізується через конектори та API.
- **Зрілість спільноти (3):** має офіційну документацію та інтеграцію з екосистемою AWS.

### Розрахунок зваженої оцінки

Для порівняння використано формулу з теоретичних відомостей:

S = Σ(wᵢ × sᵢ) / Σwᵢ

де:
- S — зважена оцінка платформи;
- wᵢ — вага критерію;
- sᵢ — оцінка платформи за відповідним критерієм.

Сума ваг дорівнює 1.

Для Eclipse Ditto:

S = 0,25 × 5 + 0,20 × 4 + 0,20 × 4 + 0,15 × 5 + 0,10 × 5 + 0,10 × 3 = 4,40.

Для Azure Digital Twins:

S = 0,25 × 3 + 0,20 × 5 + 0,20 × 3 + 0,15 × 1 + 0,10 × 3 + 0,10 × 4 = 3,20.

Для AWS IoT TwinMaker:

S = 0,25 × 2 + 0,20 × 5 + 0,20 × 3 + 0,15 × 1 + 0,10 × 3 + 0,10 × 3 = 2,85.

### Висновок

За результатами порівняння найвищу зважену оцінку отримала Eclipse Ditto — 4,40 бала. Azure Digital Twins отримала 3,20 бала, а AWS IoT TwinMaker — 2,85 бала.

Eclipse Ditto обрано для реалізації цифрового двійника електроскутера завдяки відкритому вихідному коду, підтримці різних протоколів обміну даними та можливості локального розгортання. Це дає змогу використовувати платформу без обов'язкової залежності від комерційної хмарної інфраструктури та інтегрувати її з іншими компонентами системи.
