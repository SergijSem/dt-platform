# Модель інформаційних процесів та аналіз затримок

## 1. Таблиця послідовних ділянок маршруту
Запис у сховище часових рядів та архівування команд виконуються паралельними гілками і не входять до основного послідовного ланцюга доставки поточного стану в інтерфейс.

| Ділянка | Перетворення | Затримка, мс |
| :--- | :--- | :--- |
| **Електроскутер -> DCE** | Оцифрування сигналів, первинна буферизація на бортовому контролері | 40 |
| **DCE -> DTE** | Пакування у JSON/MQTT, передача каналом зв'язку | 60 |
| **Оброблення на DTE** | Валідація пакетів, обробка бізнес-логіки та оновлення стану в API | 90 |
| **DTE -> Unity** | Опитування API кліентським додатком Unity та рендеринг | 150 |
| **РАЗОМ** | **Наскрізна затримка E2E** | **340** |

*Примітка:* Запис у сховище часових рядів (120 мс) іде паралельною гілкою і не впливає на час доставки поточного стану в інтерфейс.

## 2. Зіставлення з нефункційними вимогами
- **Перевірка NFR-01 (Синхронізація стану двійника):** Сума ділянок до платформи складає $40 + 60 + 90 = 190$ мс. Цільове значення за NFR-01 становить $\le 250$ мс. Вимога **виконана** ($190 \text{ мс} \le 250 \text{ мс}$).
- **Перевірка NFR-02 (Наскрізна затримка):** Сумарна наскрізна затримка складає $340$ мс. Цільове значення за NFR-02 становить $\le 500$ мс. Вимога **виконана** ($340 \text{ мс} \le 500 \text{ мс}$).
