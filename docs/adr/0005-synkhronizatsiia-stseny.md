# ADR-0005. Синхронізація багатокористувацької сцени

## Статус

Прийнято, 2026-11-22

## Контекст

Багатокористувацьке імерсивне середовище цифрового двійника електроскутера має забезпечувати одночасну роботу декількох клієнтів зі спільним станом. Необхідно синхронізувати положення та орієнтацію учасників, присутність у сеансі й спільні позначки з урахуванням різних мережевих умов.

Під час реалізації та перевірки використано WebSocket-сервер із частотою формування знімків 20 Гц. Вимірювання виконано для профілів LAN, City і Mobile з використанням інтерполяції та екстраполяції.

## Варіанти

1. **Централізована авторитетна модель:** сервер визначає та обробляє повний стан усіх учасників, а клієнти лише надсилають запити на його зміну.
2. **Однорангова синхронізація (P2P):** клієнти обмінюються станом безпосередньо між собою, наприклад, через WebRTC.
3. **Гібридна модель:** клієнти передають власні позиції та орієнтації через WebSocket-сервер, який перевіряє та пересилає оновлення. Сервер також контролює спільні позначки й присутність учасників.

## Рішення

Обрано **варіант 3 (гібридна модель синхронізації)** на основі WebSocket із частотою формування знімків 20 Гц.

Клієнт є джерелом власної позиції та орієнтації. Сервер перевіряє отримані координати та пересилає оновлення іншим учасникам. Сервер сеансу є авторитетним джерелом спільних позначок і присутності учасників.

Для відображення віддалених учасників використовується інтерполяція положення та сферична інтерполяція орієнтації. Додатково передбачено режим екстраполяції з обмеженням прогнозування до 250 мс.

Телеметрія електроскутера надходить безпосередньо з Eclipse Ditto, без використання сервера багатокористувацького сеансу як проміжного вузла.

## Наслідки

Позитивні:
- Забезпечується одночасна робота декількох клієнтів зі спільним станом.
- Сервер централізовано контролює створення та видалення позначок і присутність учасників.
- Інтерполяція забезпечує точне відтворення руху: максимальне відхилення в проведених вимірюваннях становило 0,2 см.
- Екстраполяція зменшує затримку відображення: для Mobile затримка p95 становить 96 мс.

Негативні:
- Затримка відображення залежить від мережевого профілю та досягає 236 мс за p95 у режимі Mobile з інтерполяцією.
- Використання TCP може затримувати актуальні оновлення позицій у разі повторного передавання втрачених сегментів. Для позицій альтернативою може бути невпорядкований WebRTC DataChannel.
- За трьох учасників вихідний потік сервера становив у середньому 110,0 кбіт/с. За збільшення кількості учасників повна розсилка має квадратичне зростання \(N(N-1)\), тому для масштабування потрібне керування зонами інтересу.
- Формування знімків відбувається кожні 50 мс. Відмова центрального сервера припиняє синхронізацію спільного стану, тому необхідно передбачити повторне підключення та відновлення сеансу.
- Канал синхронізації сцени не призначений для безпосереднього керування фізичним електроскутером. Для цього потрібен окремий захищений механізм перевірки команд.
