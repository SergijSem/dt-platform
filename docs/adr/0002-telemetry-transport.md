# ADR-0002. Використання протоколу MQTT для передавання телеметрії

## Статус
Прийнято, 2026-10-10

## Контекст
Бортовий контролер (емулятор) електроскутера передає пакети телеметрії частотою до 10 Гц. Канал зв'язку є бездротовим, тому можливі втрати пакетів, короткочасні розриви зв'язку та обмежена пропускна здатність. Нефункційна вимога NFR-05 вимагає швидкого відновлення синхронізації після збою мережі.

## Варіанти
1. **REST API (HTTP/HTTPS POST):** Простий у реалізації, але створює великий накладний трафік (заголовки HTTP) і вимагає постійного встановлення з'єднань.
2. **MQTT (Message Queuing Telemetry Transport):** Легковаговий протокол на базі TCP, розрахований на IoT-пристрої, підтримує QoS (Quality of Service) та мінімальний розмір заголовків.
3. **gRPC (HTTP/2):** Висока продуктивність і бінарна серіалізація, проте складніший у налаштуванні для мобільних/бортових клієнтів порівняно з MQTT.

## Рішення
Обрано **варіант 2 (MQTT)** як основний протокол транспортного рівня між бортовим емулятором і серверним брокером (DCE).

## Наслідки
+ Мінімальний обсяг службового трафіку та підтримка непостійних з'єднань.
+ Вбудовані механізми QoS для гарантованої доставки критичних подій.
− Потребує розгортання та адміністрування окремого MQTT-брокера (наприклад, Eclipse Mosquitto).
